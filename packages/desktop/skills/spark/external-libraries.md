# Integrated external libraries

Version-matched copy of the integration table for this Spark release. Import each library from its own package and use its upstream documentation; this table lists the version Spark patches and tested, and what changes on desktop. Install exactly that version: patches apply to exact versions, and other versions build unpatched.

| Starting application | Intended path |
| --- | --- |
| Expo mobile app adding desktop | Keep supported upstream imports; adopt framework adapters for individual missing cross-platform capabilities. |
| Electron desktop app | Map native capabilities to framework APIs and adapt the UI/runtime deliberately. Do not promise Electron's process, preload, `webContents`, or general Node runtime compatibility. |
| Existing Electron desktop and React Native mobile apps | Share application logic through capability contracts incrementally. An Electron backend could support staged adoption, but none is implemented or committed to by this policy. |

## Optional backend dependencies

Apps using `/markdown`, `/html`, `/webview`, or `/sqlite` must install the matching optional peer: `react-native-enriched-markdown@1.1.1`, `react-native-enriched-html@1.1.1`, `react-native-webview@16.0.0`, or `@op-engineering/op-sqlite@18.2.1`, and keep the SDK's overrides for WebView and SQLite (see [UPGRADING.md](UPGRADING.md)). `spark doctor` reports missing declarations. Universal apps targeting Windows exclude `react-native-enriched-html` and `react-native-enriched-markdown` in `expoByPlatform.windows.autolinking.exclude` in `desktop.config.json`; they have no Windows implementation. Spark applies the Enriched Markdown/HTML compatibility patches automatically; no package-manager patch declaration is needed.

## Windows

Windows supplies an adapter for `react-native-nitro-modules` 0.37.0 (the Nitro C++ runtime through RNW JSI). A Nitro library with only Swift/Kotlin implementations still needs its own Windows implementation. Windows external-library integrations are implemented in source but not yet verified on x64 and ARM64 hardware; WebView follows upstream Windows prop coverage.
